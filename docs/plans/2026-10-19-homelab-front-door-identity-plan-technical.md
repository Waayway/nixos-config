# Homelab front door: identity (Kanidm) — technical plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Plain-language version (what happens, who does what): `2026-10-19-homelab-front-door-identity-plan.md`.

**Goal:** Kanidm on VM 111 at `id.vanwaaij.com`, people and per-app access declared in
Nix and provisioned into it, an oauth2-proxy gate on the router for apps without OIDC,
and Proxmox signing in through Kanidm.

**Architecture:** `homelab.people` (declared once, same value on every host) and
`homelab.access.<app>` (next to the service, collected flake-wide by `tools.accessFrom`,
plus local `homelab.identity.extraAccess` for unmanaged apps) feed
`services.kanidm.provision` on the identity host. The router passes `id.*` through as
TCP (TLS terminates on Kanidm) and runs oauth2-proxy as a Traefik forward-auth gate.
Everything is tried on VM 230 (router-test plus a test Kanidm at `id-test.vanwaaij.com`)
first.

**Tech Stack:** NixOS 26.05, `pkgs.kanidmWithSecretProvisioning_1_10`
(`services.kanidm`, `.provision`), `services.oauth2-proxy`, Traefik 3.7,
`security.acme` (Cloudflare DNS-01), opnix, Proxmox `pveum`.

**Spec:** `docs/plans/2026-10-19-homelab-front-door-design.md` (section D, "Access as
code", "What can use it").

**Depends on:** the router plan (`…-router-plan-technical.md`) complete: `lib/routeType.nix`,
`tools.routesFrom`, `homelab.router.{routes,extraRoutes,echo,servicePrefix,tailnetServices}`,
hosts `router` and `router-test`, VM 230 on `10.0.10.230`.

## Global Constraints

- Kanidm domain **`id.vanwaaij.com`** (test: `id-test.vanwaaij.com`); origin
  `https://<domain>`. The domain is effectively permanent once users exist.
- VM 111, `10.0.10.111`, hostname `identity`, 1 core, 2 GB, 16 GB root, `local-lvm`.
- Credential policy: `idm_all_persons` minimum `mfa`; group `admins` minimum
  `passkey`. No password-only logins.
- Group per app: `<app>-users`; in the `groups` claim as `<app>-users@<domain>`.
- Gate login host `auth.vanwaaij.com` (test `auth-test.vanwaaij.com`), oauth2-proxy on
  `127.0.0.1:4180`, cookie domain `.vanwaaij.com`.
- Secrets generated by Claude, stored in 1Password Homelab, delivered by opnix; never
  printed: `kanidm-admin` (fields `admin`, `idm_admin`), `kanidm-oauth2-proxy`
  (`credential`), `kanidm-oauth2-proxmox` (`credential`), `oauth2-proxy-cookie`
  (`credential`, 32 random bytes base64). Test VM uses separate `*-test` items.
- Kanidm backup: `online_backup` daily to `/store/kanidm` (NFS
  `10.0.10.130:/mnt/store/internal`, already in the restic `store` repo), 7 versions.
- Same repo rules as the router plan (context file of that run): modules always
  imported, gated on `enable`; RFC nixfmt; commit own paths, no AI trailer; no push.

## Review Focus

1. A person named in `homelab.access.*.members` but missing from `homelab.people`
   fails evaluation naming both (Task 1).
2. A gated route whose access entry is missing fails evaluation instead of letting
   everyone in (Task 3).
3. A request to a gated host with a forged `X-Auth-Request-User` header and no cookie
   is still sent to login (Task 4, Step 3).
4. oauth2-proxy's `rd` redirect only goes to `*.vanwaaij.com`, never an outside URL
   (Task 4, Step 3).
5. With VM 111 down, ungated sites keep working and gated ones fail closed (Task 6,
   Step 4).
