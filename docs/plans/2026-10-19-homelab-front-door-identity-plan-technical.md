# Homelab front door: identity (Kanidm) — technical plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Plain-language version (what happens, who does what): `2026-10-19-homelab-front-door-identity-plan.md`.

**Goal:** Kanidm (official image) on VM 111 at `id.vanwaaij.com` with repo-managed
branding; people and per-app access declared in Nix and provisioned into it after every
rebuild; an oauth2-proxy gate on the router; Nextcloud, Immich, Jellyfin and Proxmox
signing in through Kanidm.

**Architecture:** VM 111 runs Kanidm via `virtualisation.oci-containers` (reusing
`modules/services/docker.nix`). `homelab.people` (declared once) and
`homelab.access.<app>` (next to each service, collected flake-wide by `tools.accessFrom`,
plus `homelab.identity.extraAccess` for apps outside NixOS) are rendered to a
kanidm-provision JSON state; a oneshot after the container starts gets a fresh
`idm_admin` password from the container (`kanidmd recover-account`) and runs
`kanidm-provision` against the API. OAuth2 client secrets are generated by Kanidm (the
official image has no secret-provisioning patch); a script copies each into 1Password
once, and consumers read it via opnix. The router passes `id.*` through as TCP and runs
oauth2-proxy (official image) as a Traefik forward-auth gate.

**Tech Stack:** NixOS 26.05; images `kanidm/server:1.11.2` and `kanidm/tools:1.11.2`
(CLI), `quay.io/oauth2-proxy/oauth2-proxy:<pinned>`; `pkgs.kanidm-provision` (1.3.0);
`security.acme` (Cloudflare DNS-01); opnix; Traefik 3.7; Nextcloud `user_oidc`, Immich
OAuth, Jellyfin SSO plugin; Proxmox `pveum`.

**Spec:** `docs/plans/2026-10-19-homelab-front-door-design.md` (section D, revised
2026-10-20: official image, override.css, secrets via 1Password, apps included).

**Depends on:** router plan and production plan complete (router 110 and prod 100 live;
`lib/routeType.nix` with `passthrough`-less routes, `homelab.router.*`, `modules/services/docker.nix`,
Renovate config).

## Global Constraints

- Domain **`id.vanwaaij.com`**, origin `https://id.vanwaaij.com` (test: `id-test.vanwaaij.com`
  on VM 230). Permanent once users exist.
- VM 111, `10.0.10.111`, hostname `identity`, 1 core, 2 GB, 16 GB root on `local-lvm`,
  `tags = [ "tag:identity" ]` (policy: owned by `tag:nixos`), `fleet = true`.
- Kanidm image pinned (`kanidm/server:1.11.2`); never skip a minor: Renovate rule
  `separateMultipleMinor: true` for `kanidm/*`, PR per minor, `kanidm/server` and
  `kanidm/tools` grouped.
- Data `/var/lib/identity/kanidm` (VM disk); `online_backup` daily to `/store/kanidm`
  (NFS), 7 versions; container unit `RequiresMountsFor=/store`.
- Branding: `modules/identity/branding/override.css` mounted read-only at
  `/hpkg/override.css` in the container (verify the path in the image; the demo used
  `<pkg>/ui/hpkg/override.css`); display name and logo set by a oneshot via the tools
  image (`kanidm system domain set-displayname`, `set-image`).
- Credential policy: `idm_all_persons` minimum `mfa`; `admins` minimum `passkey`.
- Group per app `<app>-users`; in the `groups` claim as `<app>-users@id.vanwaaij.com`.
- Gate: login host `auth.vanwaaij.com` (test `auth-test.vanwaaij.com`), oauth2-proxy on
  `127.0.0.1:4180` on the router, cookie domain `.vanwaaij.com`.
- Secrets in 1Password Homelab, never printed, never in the repo:
  `kanidm-oauth2-<client>` (field `credential`, copied from Kanidm by script),
  `oauth2-proxy-cookie` (random 32 bytes base64). No stored `idm_admin`/`admin` password
  (recovered on demand from the container).
- Repo rules (AGENTS.md): modules always imported, gated; RFC nixfmt; own paths; author
  thijs@vanwaaij.com; no AI trailer; no push without the user.

## Review Focus

1. A member in `homelab.access.*.members` missing from `homelab.people` fails evaluation
   naming both (Task 1).
2. A gated route without an access entry fails evaluation instead of letting everyone in
   (Task 4).
3. A forged `X-Auth-Request-User` header without a cookie is still sent to login; `rd`
   only redirects within `*.vanwaaij.com` (Task 5).
4. Provisioning must be idempotent and must not delete people/groups that exist only in
   Kanidm unless declared absent (`autoRemove = false`) (Task 2).
5. With VM 111 down, ungated sites keep working, gated ones fail closed, and apps keep
   their local login (Task 7, Task 8).
