How is this repo structured:

```md
- ~/.flake (root)
  - flake.nix (inputs only; outputs come from systems.nix and programs.nix)
  - systems.nix (every machine: nixosConfigurations, darwinConfigurations, deploy nodes)
  - programs.nix (packages, apps, checks and dev shells per system)
  - AGENTS.md (conventions and gotchas for coding agents)
  - docs/ (the folder for documentation)
    - fleet.md (the fleet manager)
    - plans/ (design + implementation plan per feature: <date>-<topic>-design.md / -plan.md)
    - Flake Docs/ (these notes)
  - hosts/ (one file per machine: identity and which modules are enabled)
    - workstations/ (personal machines such as laptops/desktops)
    - servers/ (anything that is a server)
    - a host is `name.nix` or `name/default.nix`
  - lib/ (custom nix functions)
    - discoverHosts.nix (reads hosts/*/)
    - mkSystem.nix (NixOS systems)
    - mkDarwin.nix (macOS systems)
    - mkHome.nix (home-manager)
    - fleetHosts.nix (which hosts are in the fleet, and their channel)
    - mkAppCategory.nix (cross-platform app categories)
    - mkDeployNode.nix (deploy-rs nodes)
    - umport.nix (recursive importer used by modules/system.nix)
  - modules/ (all configuration; every file is always imported on every host,
    each module switches its own config off by condition, see Modules.md)
    - <category>/*.nix (system modules)
    - <category>/*_home.nix (home-manager modules)
    - fleet/ (fleet agent, server, audit hook)
  - pkgs/ (our own packages; pkgs/fleet = the fleet manager)
  - secrets/ (secret management with sops-nix)
  - template/ (base image for new Proxmox VMs)
  - tests/ (NixOS VM tests)
  - wallpapers/ (my wallpapers)
```
